# CnGal 新站前端架构与迁移指导

适用项目：MainSite、MainSite.Shared、SDK.MainSite、SDK.MainSite.AspNet。保持 .NET 10、后端 API、URL、主要操作流程和既有视觉风格。

本轮修改基于 a5c14e30 和工作区已有的画廊补丁。远端网络延迟不是已确认根因；不通过扩大 SignalR 限制、固定初始化延迟或重复扫描掩盖生命周期问题。

## 1. 职责与渲染

| 项目 | 负责内容 |
|---|---|
| MainSite | 启动、认证接入、中间件、根文档、路由、资源和 HTML 缓存策略 |
| MainSite.Shared | 页面编排、展示组件、浏览器控制器、领域编辑会话 |
| SDK.MainSite | API 请求、领域映射、页面聚合、缓存、取消和错误转换 |
| SDK.MainSite.AspNet | HTTP/Circuit 身份、令牌快照、刷新和宿主传输适配 |

默认静态 SSR。公开详情、首页和搜索保持静态；搜索继续使用 GET 表单和 URL 参数。既有编辑页、后台及业务页面保留当前 InteractiveServer 和预渲染选择，不在 App、Routes 或布局整体启用交互。

展示组件不请求 API 或加载脚本；业务交互根管理请求与提交；浏览器组件处理滚动、选择、动画和拖动。只在页面或明确的业务根声明渲染模式，内部组件继承它。

当前局部业务根包括收藏、评论、评分、个人游玩记录、工具箱、登录会话及看板娘开关。内部评分动作、展会卡片、Steam 工具栏、审核对比和看板娘内部不重复声明模式。

## 2. 浏览器生命周期

`CnGalWebSite.MainSite.Shared.lib.module.js` 是唯一初始化入口，保留中文输入法提交事件，并注册 cg-image-gallery、cg-carousel、cg-edit-nav 及受 Blazor 管理的 cg-owned 宿主。普通点击通过 site-shell 的事件委托处理。

浏览器组件采用 Light DOM；专用实现放在同目录 .razor.js。

```javascript
mount(root, { signal }) => ({ update(), dispose(), suspend?(), resume?() })
```

- 连接后才导入专用模块；模块返回后检查连接代次、连接状态和取消信号。
- 断开立即取消并释放；旧初始化任务不能挂载到重新连接的元素。
- 初始 DOM 就绪、enhancedload 和增强导航结束后更新已连接实例，不扫描文档查找组件。
- 导航开始和 pagehide 暂停轮播、关闭画廊；BFCache 恢复时重新更新。
- 画廊和轮播各自观察局部数据内容，忽略自身样式与计数修改。更新合并到微任务，不保存整棵 DOM 快照。
- 根事件委托读取当前子节点，并排除嵌套实例。节点不完整时保持后续更新机会。
- cg-owned 只负责 DOM 移除时释放控制器；其初始化和参数同步由所属 Blazor 组件负责。两种挂载机制不能同时管理同一控制器。

画廊保留原参数与图片项类型，使用真实原图链接和原生 dialog。弹层不移到 body，多个弹层使用带所有权的滚动锁。CgModal 由 IsOpen 控制，Esc/遮罩请求 OnClose，程序关闭不回调。

Markdown、裁剪、图表、抽奖动画、验证码和看板娘使用实例工厂。模块只能共享库加载 Promise、定义和不可变配置；实例分别持有 DOM、回调、计时器和观察器。第三方 Live2D 引擎目前仍只支持一个站点看板娘宿主，不能据此宣称支持多个独立 Live2D 引擎。

## 3. SDK、身份与缓存

### 身份和传输

ICurrentUserAccessor 显式区分 Unknown、Anonymous、Authenticated，并提供身份代次。无可信身份不能当作匿名。保留 SessionTokenStore、CircuitTokenStore、AuthenticationCircuitHandler 和现有审核用户缓存。

Core 只有一个完整业务 Client 清单，并提供宿主客户端创建回调。AspNet 从调用作用域创建令牌处理器，通过非拥有式桥接使用工厂传输，应用作用域只释放自己的外层资源。任意网址的转载抓取 Client 不附加站点令牌。

SDK 请求默认不可重放。QueryServiceBase 的只读 GET 显式设置 AllowReplay，允许一次带抖动退避的瞬态重试及必要的 401 刷新重发。命令、写操作和未经确认的 POST 不自动重发，即使某些写接口使用 GET。保留原有总预算与单次尝试预算，不叠加弹性管线。

调用方取消传播取消异常；超时、HTTP、业务和格式失败分开处理。响应及时释放，私人响应正文不写入普通日志。请求期间切换身份时拒绝旧结果。

用户菜单和用户背景的 SSR 请求关联当前 HttpContext.RequestAborted；交互实例在参数变化、移除时取消自己的请求，并在返回后核对请求代次。HttpContext 只由 SSR 级联参数提供，不保存到 Circuit 服务。

### SDK 数据缓存

PublicDataCache 统一按 API 来源和失效代次封装公共缓存。每次查询先通过 BeginQueryAsync 捕获可信身份与缓存代次，不能在服务构造时固定 Circuit 身份。当前选择保守策略：全部现有公共 Query 缓存仅在明确匿名时读写；登录或身份未确定时直接查询。词条、文章、视频、标签和周边的待审核内容不会进入匿名缓存。

CommandServiceBase 的写请求出口（含异常或结果不确定）推进同一 API 来源的公共缓存代次，旧式 GET 管理命令显式接入；只读任务列表 POST 不触发失效，相关详情、列表及在途回填一起失效。这里使用粗粒度来源失效，避免维护散落的关联键清单；旧代次依靠现有短 TTL 清理，不主动遍历缓存。审核用户缓存继续使用原有用户/权限分区和有界淘汰机制。

缓存对象按只读快照使用。首页返回独立记录副本组合随机推荐，不修改共享对象。SDK 内存失效不等于 CDN 或其他服务副本已经失效。

### HTML 缓存

PublicHtmlCachePolicy 为唯一应用策略。HTML 默认 private, no-store；仅页面通过 PageResponseState 确认主数据成功、匿名 GET 的成功响应、无 Set-Cookie、无影响输出的 Cookie/身份头，且路由在以下名单中时，允许五分钟 CDN 共享：

- 首页 `/`、搜索 `/search`。
- 词条、文章、视频、标签和周边的 `/.../index/{数字ID}`。

登录、MiniMode、交互页面、错误响应和其他路由均不共享。主题不生成服务器 HTML 变体，由首屏 Cookie/系统偏好引导处理。CDN 自身必须对认证、MiniMode、身份头及其他影响输出的 Cookie 绕过已有缓存，不能仅依赖回源响应头。

## 4. 页面聚合与编辑会话

IEntryPageQueryService.GetAsync 返回 SdkResult<EntryPageModel>。主数据失败使页面失败；评分、周边、目录和记录使用命名结果段显示局部失败，非游戏评分为空。SDK 并行编排请求，失败或取消后观察所有已启动任务。页面取消旧请求并核对代次，避免旧结果覆盖新路由。

文章、视频、标签和周边也通过各自的类型化页面 Query 聚合主数据与编辑记录，页面不再保留并发请求细节。评分和评论根接收初始数据，业务动作后才刷新。其他页面只有实际需要多接口编排时才增加领域聚合，不引入通用页面基类或万能 ViewModel。

SDK 查询模型中的可空 required 成员显式配置 JsonIgnoreCondition.Never，保留 null 字段。Blazor 默认省略空值，而还原时会检查 required 成员；初始模型中缺失这些字段会使整个组件操作批次失败，不能只检查收藏等单个按钮。

Entry、Article、Video、Tag、Periphery、Lottery、Space、FavoriteFolder 各自拥有编辑会话。收藏夹保持原有直接保存语义，不增加不存在的草稿格式。页面负责路由、展示与实际组件引用；会话管理模型、原始值、恢复、提交、取消和生命周期。

EditDraftStore 保留原有 LocalStorage 序列化、键名和 JSON 结构。DraftSaveLoop 每十秒串行保存修改后的快照，提交/丢弃共用互斥入口。保存与提交前合并编辑器输入；Markdown 使用输入代次拒绝重置前的旧回传。

七种有草稿的领域会话组合 EditDraftController<TDraft>，统一管理原始快照、恢复、修改检测、自动保存、提交防重入和取消释放；加载、校验、SDK 写入、提示与跳转留在领域会话。自动保存、提交、丢弃及离开前保存共用 DraftSaveLoop 的同一互斥入口，业务提交成功后在持锁期间调用 CompleteAsync，不再次加锁。FavoriteFolder 保留直接保存流程，不接入草稿控制器。

八个编辑页使用 EditSessionHost<TSession> 管理当前路由会话的事件订阅、切换代次与释放，不通过页面基类复用。页面负责创建领域会话及提供渲染调度、输入同步回调。各领域侧栏仅保留导航配置和领域扩展，公共 CgEditSidebar 统一渲染状态卡、导航和操作区并持有对应 CSS；词条 Steam 导入通过 BeforeContent 插槽保留。

柱状图、折线图和饼图组合 CanvasChartController，统一模块/控制器的创建、重试、错误状态和释放。图表组件保留自己的参数及数据转换；控制器将创建、更新、重试和释放串行化，防止并发渲染重复挂载。布局变化后的重绘由浏览器 ResizeObserver 驱动。

读草稿失败时暂停自动保存并提示，不能覆盖无法读取的草稿。仅明确提交成功或用户丢弃时删除。失败和不确定结果保留草稿；导航时取消并等待会话任务。裁剪和拖动只在浏览器执行，返回最终结果。

## 5. SEO、主题和通知

CgPageMeta 是页面唯一 HeadContent 所有者，内部组合 metadata、JSON-LD 和附加 head 内容。CgStructuredData 只输出数据标签。App 不订阅页面 meta 的反向通知。

主题以 cg-theme Cookie 持久化，无有效值时跟随系统；一次性兼容旧 LocalStorage 值，之后不双写、不在服务构造时写默认 Cookie。MiniMode 影响 SSR，继续保留服务端判定及原有恢复语义。

九宫格抽奖只向 .NET 请求业务结果，逐帧选中动画在浏览器执行；管理首页轮询使用可取消、可等待的串行循环。Toast 展示、数量限制和退出时间由浏览器处理，C# 通过 ICgToastService 适配器发送。抽屉和返回顶部使用浏览器委托。重连提示保持非阻塞，服务端业务点击在断连时受限，静态内容和本地画廊仍可使用。

## 6. 资源与发布

本地 HTML 资源引用使用 Assets；JS 导入使用框架 import map 中的逻辑路径。公共模块由宿主统一配置框架指纹，禁止手写时间戳或内容哈希。

Razor/CSS/模块、初始化入口和静态资源清单必须作为同一个完整发布产物部署，不能只覆盖单个脚本。现有 Docker 流程已提供 latest 和完整 SHA 标签，部署与回滚使用不可变 SHA，保留上一版镜像。

部署环境还需要落实：

1. 首次缓存修复发布时清理旧公共 HTML，重启所有实例以丢弃旧内存缓存；安全基线之前的镜像不能用于回滚。
2. 保留上一版指纹资源，或在当前 `/_content/`、`/_framework/` 静态请求返回 404 时，仅对静态资源回退到上一版镜像。不能把业务请求回退到旧应用。
3. 指纹资源可长期缓存；HTML 按统一策略处理。旧资源的保留窗口覆盖仍受支持的旧页面会话，不能随新镜像发布立即删除。
4. 多副本缓存通过短 TTL 收敛；此轮不新增分布式缓存和失效总线。

仓库没有当前 CDN 与部署代理配置，本次没有执行镜像发布、CDN 清理或线上配置变更。

## 7. 核对与后续验收

本次遵循“不编写或运行测试”的要求：仅检查源码、调用关系、引用、语法与差异，不构建、不运行测试、不启动浏览器或应用。语法检查不等于编译通过或运行验证。

后续发布验收尚未执行：

- 首次访问、刷新、增强导航、前进后退及内部 DOM 更新。
- 模块/图片延迟或失败、分批节点、加载期间离开页面、多实例与重复进入。
- 弹层焦点和滚动恢复、断连后静态内容及画廊可用。
- 匿名、不同用户、隐藏内容、待审核预览和缓存失效竞争。
- 取消、超时、401、提交结果不确定、草稿恢复及丢弃后旧输入回传。
- SSR 标题、描述和 JSON-LD 同时完整；编辑、上传与原 URL 兼容。

默认支持现代桌面与移动浏览器近两代版本，不增加旧内核兼容框架。
